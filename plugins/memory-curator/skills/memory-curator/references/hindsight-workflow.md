# Hindsight 记忆路由与策展

仅在目标是 Hindsight 项目 bank 时读取。`memory-curator` 负责范围、健康判断和策展结论；可用时复用已安装的 `hindsight-memory` skill 处理项目绑定、来源记录、调用与弱连接契约。该 skill 缺失时按本工作流和当前 MCP schema 执行，不将缺少 skill 当成缺少 MCP。复用现有 MCP，不新增服务、SDK、后台队列或文件↔bank 同步。

## 1. 确认项目、服务与授权

- 按当前工具发现识别 MCP 及其 Harness 前缀：存在本地 **Hindsight 项目记忆** 时优先本地；本地不存在而云端 **Hindsight Project Memory Cloud** 存在时使用云端；两者都不存在时，将本任务 Hindsight 路径记为 **disabled**。
- disabled 只表示本任务不调用服务，不卸载插件、不修改远端配置。回到 [文件定位与 route/curate 流程](../SKILL.md) 处理已有文件库；未找到文件库时继续输入充分的原任务，不自动创建文件库或 bank。
- 仅在启用 Hindsight 路径时，从项目记忆入口或当前任务取得明确的 `project_id → bank_id`；缺失或歧义时报告缺口，不从路径/仓库名猜测、不使用 `default`。`list_banks` 只能帮助核对已授权项目，`get_bank` 成功不等于获得写权限。
- 选定入口后读取所需 MCP schema，以及可用的 `hindsight-memory` skill，每个 scoped 调用传入显式 bank。工具存在不证明调用成功；调用失败或结果未知也不等于入口缺失。未确认写入保留原 ID 与状态，按所选服务的既有弱连接契约处理，不改投另一入口重复提交。
- 区分普通任务取上下文、只读审计和已授权策展。新增经验、纠正及可逆失效在既有任务授权范围内直接执行；审计授权不自动变为修改授权，永久删除仍须先列清单确认。
- 本地 MCP 是连接入口。服务的抽取、embedding、重排、consolidation 或 `reflect` 可能使用配置的远程模型；不得声称全离线，也不借此扩大数据外发授权。

## 2. 按任务取证

### 普通任务：有缺口才 recall

将当前缺口写成一个有界问题，例如“此前采用这个绕法的版本条件和证据是什么？”按当前 MCP schema 调用 `recall`，限制返回预算，只读取真正相关的来源。结果要与当前任务、版本、观察时间核对；必要时用 `get_memory` / `get_document` 回查原记录。

没有相关命中不证明 bank 为空或健康。检索不可用时记为 unavailable；输入充分的工作继续，只有依赖缺失证据的判断保留未决。`reflect` 仅用于需要综合的具体问题；生成结论仍需证据，不能替代当前事实、正式规则或 owner 验收。

### 专门审计：范围内分页列举

先明确 bank、主题/标签/类型、时间范围（若需在返回结果中筛选）、是否包括失效历史，以及期望覆盖度。记录审计开始时间与过滤条件；不把 `recall` top 命中当作全库清单。

1. 用 `list_memories` 列事实、`list_documents` 列来源容器，按当前 schema 的 `limit/offset` 分页；固定过滤条件，按实际返回条数推进，记录去重后的 ID 和已读页数。文档数与事实数无须相等。
2. 对返回 `total` 的接口，覆盖该范围全部结果后才声称列举完成；若提前空页、分页失败、总量变化或缺少可靠结束信息，报告未覆盖部分，不给出全库健康结论。全库审计优先不用 `q`/标签筛选；服务不提供稳定快照时，说明这是该次列举的覆盖结果。
3. `list_documents(q)` 的 `total_is_estimate=true` 表示结果受限，不能按该 total 宣称穷尽；收窄/分段查询或改用不带 `q` 的分页。标签 `any/all` 会包括无标签事实，限定严格子集时用 `any_strict/all_strict` 或 `exact`，并记录选择。
4. 当前接口若无法枚举失效记录或指定范围，明确排除项；已有失效 ID 可单独读回，不能以此推断已覆盖全部失效历史。
5. 紧凑清单只用于筛候选。对疑似冲突、重复、过期或待修改项，读取完整事实与所需来源文档，再做判断；永久删除前须读原文和全部受影响记录。不要把所有正文一次装入上下文。

## 3. 六维判断按服务语义解释

| 维度 | Hindsight 检查 | 判断边界 |
|---|---|---|
| **过期** | 原事实的发生/提及时间、版本、适用条件与当前来源是否仍一致 | 旧事件仍可是真实历史；优先纠正适用范围或使失效建议退出 active，不因年代久远直接删除经验。 |
| **重复** | 是否同一来源/事件重复提交、重复表达同一结论且没有独特证据 | 一文档抽取多个事实、独立来源相互印证、raw fact 与派生 observation 并存均不自动算重复。 |
| **矛盾** | 同一对象、条件和有效时间内，结论是否互斥 | 新旧状态更替或条件不同可合理并存；以证据核对，不能只因时间较新就覆盖另一条。 |
| **孤儿/死链** | 声称的来源、document ID 或事实关联能否读回，来源是否支持结论 | `document_id` 可选，未挂文档不等于孤儿；读取失败先区分权限/不可用/确实缺失，不套用文件三方计数。 |
| **碎片** | 同一经验的条件、方法、结果是否散落且妨碍使用 | 可写有来源的综合经验并保留关联；不是强制一事实一文档，也不自动删除组成事实。 |
| **易误判/证据不足** | 高频变化状态、绝对判断、实体错配、来源缺失或结论超出证据 | 标注未核实与适用限制；派生总结和 recall 排名不是新的事实证据，仍需原来源。 |

保留有独特价值的“为什么失败、何时有效、如何复现”。永久删除只在读原记录后，确认无需保留独特经验并取得明确授权时考虑。文件判删矩阵提供判断思路，不能直接转成服务删除命令。

## 4. 选择最小动作

用 `bank / memory或document ID | 拟定动作 | 原文与证据 | 影响范围 | 授权情况` 记录策展清单。已授权的非永久删除动作可以直接执行并报告结果；待确认删除与其它工作分开处理。

| 目的 | 当前 MCP 动作 | 执行与读回重点 |
|---|---|---|
| 保留 | 不写入 | 记下理由；来源暂时不足不冒称已核实。 |
| 新增经验证经验 | `retain` | 保留 source、稳定 `document_id` 与精确提交文本 hash，遵守当前工具的 operation 契约（可用时参照已安装 skill）；不要重复导入全文历史。 |
| 纠正抽取错误 | `update_memory` | 先读 raw `world/experience`。仅提交要改字段；刻意纠正时设 `resolve_entities=false`，实体参数替换整组而非追加，需保留仍正确的实体。读回正文、实体及时间/类型等实际改动字段。 |
| 退出活跃集/恢复 | `invalidate_memory`，恢复时 `restore=true` | 仅 raw `world/experience`，保留原因、原 ID 与相关前态。失效是可逆软退役，会影响 recall、consolidation 和派生关联；读回原生 `state`，不能只靠 recall 未命中确认。恢复还要核对正文、实体和来源，不能只看到 `state=valid` 就声称完整恢复。 |
| 汇总碎片/替代旧结论 | `retain` 或有依据的 raw 纠正，必要时逐条失效旧 raw | 保留来源、原 ID、替代范围和不同条件；先核对新结论的写入结果，再处置旧项。没有原子“合并”承诺，分别记录每步状态。 |
| 永久删除 | 仅使用当前实际提供且有权限的删除接口 | 当前本地 MCP 的 `delete_document` 会永久删除文档及其全部关联记忆；先读原文及受影响记录，列清单确认后执行。没有单事实删除接口时，不能扩大成整个文档删除。 |

`observation` 是派生内容，不能直接 `update_memory` 或 `invalidate_memory`。先找到支撑的 raw facts 和来源，纠正/失效实际有误的 raw，再读回服务重算结果。若 raw 正确而派生仍错，报告派生问题与未决范围，不伪造 raw 变更来“修复”总结。

权限不足或接口缺失时，保留具体对象与拟议动作，不通过另一服务身份、删除重建文档或创建 bank 来绕过。不要把文件删除、文件索引更新与 bank 变更相互自动触发。

## 5. 以原生完成和读回验收

- 保留 bank、来源/source ref、document、memory 与 operation ID，以及提交内容 hash、最近状态和读回结果；未返回的 ID 留空，不虚构。
- 异步 `accepted`/`SUBMITTED` 仅表示已接收。对返回的 operation ID 使用 `get_operation`，分别报告 pending/processing、completed、failed、cancelled、not_found 或 UNKNOWN；失败与未知不能标成完成。沿用所选服务的重试/弱连接契约（可用时参照已安装 skill），不再增加 Agent 重试循环。
- 异步操作达到原生 completed 后，用 `get_document` / `get_memory` 核对来源、实际内容与目标变化。同步动作若没有 operation ID，以原生响应和对应读回核对，不制造一个轮询对象。服务文档 hash 与提交原文 SHA-256 可能使用不同规范化，不要求两者相等；metadata 中原提交的 `content_sha256` 仍指原文，raw fact 编辑后不能把它当作 fact 新正文的 hash。
- `get_memory` 的 `state`、失效原因/时间及编辑、consolidation 时间可用于核对生命周期，仍要检查相关内容字段。恢复后即使 `state=valid`、正文存在且 consolidation 时间已更新，原有实体集合也可能仍为空；恢复验收要对照保存的前态，报告具体差异，必要的显式纠正须有原证据且在授权范围内，不能声称服务自动恢复全部关联。
- 永久删除核对原对象及关联影响；已知对象的权限错误/服务不可用不能当作删除成功。纠正或失效涉及派生 observation 时，另外报告重算读回是否确认；raw 成功不等于所有派生内容已验证。
- 单项完成不等于全库审计完成。结束时报告目标范围、列举覆盖、已完成/待处理动作、原生状态与证据、未核实项。范围不完整写 partial，服务不可用写 unavailable；健康结论只限实际已覆盖范围。

不运行 `check-index.sh` / `governance-check.sh` / `mark-curated.sh` 验收 bank，也不为其制造 `MEMORY.md`、`.curator-index.json` 或 `.curator-state`。同一轮含文件库时，文件门禁和 bank 验收分别报告。

## 6. 经验学习闭环

在任务或重要单元结束时，将有来源、经验证的有效方法、失败原因、适用条件和未确认点作为经验贡献；以后具体任务 recall 时检验它是否仍适用。重复出现且可复现的经验可用于提出测试或 skill 改进，并在相应修改授权内实施、验证。记忆或 `reflect` 结论不自动改写 AGENTS、正式规则、skill 或 owner 决策。

操作完成证明流程可用，不证明任务质量、效率或 token 收益。需要评估这些收益时使用 [Hindsight 评估协议](hindsight-evaluation.md)，单列新证据，不覆盖既有文件路径验收历史。
